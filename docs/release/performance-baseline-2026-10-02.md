# Astro 上线后性能基线

测试日期：2026-10-02（Asia/Shanghai）。生产版本 `8bbde7c4`，Lighthouse 13.5.0，Chrome 155。本轮仅测量，无应用代码修改或重新部署。

## 方法与边界

- 测试正式域名首页及 `/posts/javascript/PWA/2019-02-18-progressive-web-apps-blog.html`。
- Lighthouse CLI 独立临时 Chrome profile、默认冷加载和模拟节流；仅 Performance 类别。移动端 412×823、约 1.6 Mbps、150 ms RTT、4 倍 CPU slowdown；桌面端使用 desktop preset。
- 每个组合先测一次；两次桌面初测出现加载超时警告，延长 max-wait-for-load 至 90 秒复测，保留所有原始报告。不是多轮中位数，也不是 CrUX 真实用户数据。
- 本机至 CDN 的链路、第三方服务和测试机器状态会影响结果，不能将模拟时间直接等同于每位访客的体验。TBT 不能代替真实 INP 或滚动帧率。

## 证据与优先级

1. **树叶背景**：首页移动报告将 `.canopy` 识别为 LCP；JPEG 约 683 KB，资源在 CSS 后才被发现，没有高优先级提示。报告估计现代格式可节省约 497 KB。先做 WebP/AVIF 与尺寸适配，再处理首屏资源发现顺序。
2. **字体**：首页移动测试下载 32 个字体请求，约 1.58 MB；霞鹜文楷普通 / 粗体分片占大头。建议保留字体设计，评估实际字符子集和首屏加载策略，避免直接把所有字体 preload。PWA 移动 CLS 0.092，报告主要归因于字体替换后目录与正文位置变化。
3. **头像**：约 400 KB PNG，在作者侧栏未打开时已下载；当前侧栏只显示 88×88。建议生成适配分辨率资源，按需加载。
4. **文章大图**：PWA 原文图片单张约 2.60 MB，该页整轮传输约 5.38 MB；可提供压缩显示版本，保留原图供点击查看。
5. **图标字体**：Font Awesome 约 72 KB，`font-display:block` 被报告指出约 3 秒可见性等待。后续可替换为实际使用的 SVG 图标或子集，保留导航布局。

首轮两份移动报告 TBT 均为 0 ms，因此不应凭这次加载分数直接归因于伊布或玻璃动效；它们的滚动 / 点击流畅度需要单独运行时测量。
